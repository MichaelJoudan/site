    01

    Know what you are actually buying

    Three separate things get muddled together by every hosting advert you will see. Keeping them apart is what stops you overpaying.

    1. The domain name — the address people type. You rent it yearly from a registrar. Around US$11/year for a .com. This is the only thing you must pay for.
    2. The hosting — the machine that serves the files. GitHub Pages does this free for static sites like yours, including the HTTPS certificate.
    3. The site itself — the files. Already built. It is plain HTML, CSS and JavaScript with no server and no database, which is exactly why the hosting is free.
    The one thing to internalise A domain is rented, not owned. If the card on file expires and the renewal fails, the name goes back on the market and someone else can take it. Turn on auto-renew and keep the card current.
    02

    Choose the name

    Pick something you will still be comfortable putting on a CV in ten years. Personal names age better than clever project names, because the project will change and you will not.

    Reasonable candidates for you

    PatternExampleReads as
    First + last namejiaheng.comThe durable default. Works for any future role.
    Name + countryjiaheng.sgCredible locally; signals you are based in Singapore.
    Name + initialjayheng.coGood fallback when the plain name is taken.
    Subject nameintelligencebase.ioFine if the site outgrows you — riskier if it does not.

    Rules that save money and embarrassment

    • Check the renewal price, not the first-year price. A $1 first year with a $40 renewal is the standard trap. .io and .ai renew expensively; .com, .co and .sg are stable.
    • No hyphens, no numbers. You will have to read the address out loud eventually.
    • Say it out loud once. If it needs spelling, pick another.
    • .sg has a catch. It requires a Singapore presence and identity verification through an SGNIC-accredited registrar. Fine for you, slower to register than a .com.
    03

    Register it

    Any of these three is a sound choice. All include WHOIS privacy free, which keeps your name, address and phone out of the public registry — worth having on by default.

    Registrar.com, per yearTrade-off
    Cloudflare Registrar~$10.44 flatSold at cost, no renewal jump ever. You must use Cloudflare's nameservers — which is fine here, and gives you a good DNS panel for free.
    Porkbun~$10.99 flatSame price in and out, no nameserver requirement, clean interface. The easy default.
    Namecheap~$6 then ~$14Cheap first year, dearer after. Widely used and reliable; just know the renewal number.
    Skip the upsells At checkout you will be offered hosting, email, SSL, "site protection" and premium DNS. You need none of them — GitHub Pages provides the hosting and the certificate. Buy the domain and nothing else.

    Before you close the tab

    • Turn auto-renew on.
    • Turn WHOIS privacy on (usually on by default at all three).
    • Turn two-factor authentication on. Your registrar account is the single point of failure for the whole site.
    • Confirm the verification email the registry sends. Ignore it for 15 days and the domain gets suspended.
    04

    Put the files on GitHub

    GitHub is where the files live. You do not need to learn Git for this — the whole thing can be done by dragging files into a browser window.

    1. Create a free account at github.com/signup, verify the email, and turn on two-factor authentication.
    2. Click New repository. Name it site. Set it to Public — Pages is free only on public repositories. Leave everything else alone and create it.
    3. On the empty repository page, click uploading an existing file.
    4. Unzip the site folder on your machine, then drag the contents in — index.html, the assets folder, .nojekyll, tools. Not the outer folder itself: index.html must sit at the top level of the repository.
    5. Click Commit changes.
    Repository root → index.html  ·  assets/  ·  .nojekyll  ·  tools/  ·  README.md
    Why .nojekyll GitHub runs a blog engine over Pages sites by default and quietly skips files and folders starting with an underscore. The empty .nojekyll file turns that off. It is already in the folder — make sure it uploads.
    05

    Switch the hosting on

    1. In the repository, go to Settings → Pages.
    2. Under Build and deployment, set Source to Deploy from a branch.
    3. Set the branch to main and the folder to / (root). Save.
    4. Wait about a minute, then reload the page. A green banner appears with your live URL.
    https://<your-username>.github.io/site/
    Checkpoint Open that URL. The site should load exactly as it does locally. If it does, hosting is done and everything that follows is only about the address.
    06

    Point the domain at it

    Two halves, and they must both be done: tell GitHub which name to answer to, and tell the name where to find GitHub.

    Half one — tell GitHub

    In Settings → Pages → Custom domain, enter www.yourdomain.com and save. GitHub writes a file called CNAME into the repository. Leave that file alone; deleting it disconnects the domain.

    Half two — tell the domain

    In your registrar's DNS panel, add these records. Click any value to copy it.

    TypeName / hostValueWhy
    A@The four IPv4 addresses GitHub Pages answers on. Add all four — they are load-balanced, not alternatives.
    A@
    A@
    A@
    CNAMEwwwSends www to your Pages site. Note the trailing .github.io and no repository name.
    AAAA@Optional IPv6. Add all four if your panel supports AAAA; skip the set entirely if it does not.
    AAAA@
    AAAA@
    AAAA@

    @ means the bare domain (yourdomain.com). Some panels want it written as the domain itself or left blank — the panel's own help text will say which.

    Now wait DNS changes can take up to 24 hours to spread, though 10–30 minutes is typical. GitHub will show an amber "domain does not resolve" warning during this window. That is expected — do not change anything, and do not re-enter the domain repeatedly.
    07

    Turn on HTTPS and check the result

    1. Once the warning clears, return to Settings → Pages and tick Enforce HTTPS. The certificate is issued automatically and free; the tick box can take up to 24 hours to become available.
    2. Visit all four forms and confirm each lands on the site: yourdomain.com, www.yourdomain.com, and both with https://.
    3. Open it on your phone. Check the map pans, a country sheet opens and drags closed, and nothing scrolls sideways.
    4. Switch your phone between light and dark mode and reload.
    You are live At this point the site is public and shareable. Everything after this is maintenance.
    08

    Change it later without breaking it

    Every piece of content on the site comes from one file: assets/js/data.js. Adding a market, a strategy or an event is editing one object in it.

    1. In GitHub, open assets/js/data.js and click the pencil icon.
    2. Edit. Keep the commas and braces exactly as they are — a stray comma is the one thing that will blank the page.
    3. Commit changes. The live site updates in roughly 30 seconds.
    4. If it looks unchanged, hard-refresh: Cmd/Ctrl + Shift + R.
    The undo you actually have Every commit is a restore point. If an edit breaks the page, open the repository's Commits tab, find the last good one, and revert it. Nothing you do here is unrecoverable.

    When it does not work

    What you seeWhat it meansWhat to do
    404 at the github.io URLNo index.html at the repository rootCheck the file list. If everything sits inside a subfolder, move index.html and assets up one level.
    "Domain does not resolve to the GitHub Pages server"DNS has not propagated, or a record is wrongWait 30 minutes first. Then re-check the four A records and that the CNAME value has no repository name in it.
    "Enforce HTTPS" is greyed outThe certificate has not been issued yetWait. It needs DNS to be correct and can take up to 24 hours. Nothing to fix.
    Site loads, page is blankA JavaScript error, almost always a typo in data.jsOpen the browser console (F12). It names the line. Or revert the last commit.
    Domain worked, then stoppedThe CNAME file was deleted by a later uploadRe-enter the custom domain in Settings → Pages.
    Map is blank, everything else fineassets/js/world.js did not uploadIt is a large file. Re-upload it on its own.
    ALT

    If you would rather not use GitHub

    Two equally free alternatives, both of which take a drag-and-drop of the site folder and give you a live URL in under a minute:

    • Netlify Drop — drag the folder onto app.netlify.com/drop. Custom domain and HTTPS are in the site settings. Simplest possible path.
    • Cloudflare Pages — the same idea, and if your domain is already at Cloudflare the DNS is filled in for you.

    The DNS records differ slightly between hosts, but every step above maps one-to-one. Avoid shared cPanel hosting and WordPress plans for this site — you would be paying monthly for a database you do not have.

    One thing worth checking first You work at a regulated firm in Singapore. Most banks and asset managers have an outside-business-activity or personal-publication policy that covers a public site discussing markets, even a personal one. Check with compliance before you point the domain at it — a five-minute email now is much cheaper than taking it down later. The site already carries a "personal research, not investment advice, not the views of any employer" line in the footer; that helps, but it is not a substitute for asking.
